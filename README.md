# Схем-Мост GTNH

Локальный веб-конвертер схематик для Minecraft 1.7.10 + GregTech New Horizons:

**.litematic / .schem (Sponge) / .schematic → legacy .schematic для Schematica**

Работает полностью офлайн — файлы никуда не отправляются.

## Почему это нужно

- Новые форматы (.litematic, .schem) 1.7.10 не читает вообще.
- Универсальные онлайн-конвертеры пишут числовые ID из *чужой* сборки: Forge 1.7.10
  назначает модовым блокам динамические ID при первом запуске, поэтому у каждого
  игрока своя карта ID — отсюда «камень превращается в дверь».
- Новые блоки (бетон, дрипстоун, точильный камень...) в 1.7.10 не существуют —
  их надо осознанно заменять.

Этот конвертер читает карту ID из `level.dat` **твоего** мира (раздел FML ItemData),
палитру — в диалоге, спорные блоки — вручную.

## Что нового

### v1.0.5 — фиксы схем с shulkr.com (шаг «Схема»)

- **.schem от shulkr.com теперь читается.** Оказалось, что shulkr пишет
  Sponge Schematic **v3** (палитра и данные блоков спрятаны в compound
  `Blocks: { Palette, Data }`, а не лежат в корне, как в v1/v2) и в
  **big-endian**, хотя спека .schem требует little-endian. Из-за этого
  парсер раньше видел мусорный корень и отказывался с «missing Palette».
- **Фикс «молчаливого мусора» при неправильной endianness**: новый
  `parseNbtSane` пробует обе endianness и выбирает ту, где ключи корня
  выглядят как настоящие имена (мусорный разбор склеивает все ключи в
  одну бинарную строку — это и отсекается). Применён ко всем парсерам:
  sponge, litematic, legacy и level.dat.
- **.litematic от shulkr.com** — тоже big-endian, теперь читается тоже.
- Проверено на реальных файлах: `angel-statue.schem` и
  `angel-statue.litematic` (188×118×48, 23 828 блоков) дают идентичный
  результат анализа и конвертируются; все прежние фикстуры (фермы,
  склады, тестовые дома) — без регрессий.

### v1.0.4 — диагностика ошибок разбора (шаг «Схема»)

- **Понятные ошибки вместо «Не удалось разобрать файл»**: если загрузка
  схемы падает, сервер пишет в консоль блок `[analyze] отказ: …` —
  имя файла, размер, первые байты и точную причину (какой парсер и почему
  не смог). Тот же текст теперь виден в тосте на странице.
- **Распознавание чужих форматов**: ZIP-архив («распакуй и загрузи файл
  внутри»), structure block .nbt, Bedrock .mcstructure, текстовый файл
  (HTML вместо схемы), пустой/обрезанный файл, битый gzip.
- **zstd-сжатие .schem** (новые WorldEdit/FAWE) — читается автоматически,
  если Node.js 22.15+ (в более старых Node будет внятное сообщение).
- **Старые .litematic (1.12–1.15)**: BlockStates в виде byte array с
  varint-индексами — теперь тоже читается (раньше давал пустую схему).
- **Фикс NBT-писателя**: в little-endian режиме длины строк/массивов и
  long'и ошибочно писались big-endian (на экспорт legacy .schematic не
  влияло — он big-endian, но теперь корректно в обе стороны).
- Формат определяется по структуре NBT (Regions / Palette / Blocks),
  а не только по расширению файла.

### v1.0.3 — фиксы level.dat и Windows-базы

- FML ItemData в реальных level.dat лежит в корне NBT — поддержаны оба
  варианта; фикс Prisma «Error code 14» на Windows (абсолютный путь к
  prisma/custom.db, команды через scripts/db.mjs).

## Быстрый старт

Нужен Node.js 20+ (или Bun 1.1+).

```bash
npm install        # или: bun install
npm run db:push    # создать базу SQLite (или: bun run db:push)
npm run dev        # или: bun run dev
```

Открой <http://localhost:3000>.

В архив уже входит база с демо-профилем «GTNH Test» (синтетический level.dat,
29 модов / 291 блок) — можно потыкать сразу, без своего level.dat.

## Как пользоваться (4 шага)

1. **Профиль** — перетащи `level.dat` своего мира. Путь в GTNH-инстансе:
   `saves/<имя мира>/level.dat`. Профиль сохранится и будет переиспользоваться.
   Нет level.dat под рукой — жми «Пропустить» (моды проверяться не будут).
2. **Схема** — перетащи `.litematic`, `.schem` или `.schematic` (формат
   определяется автоматически).
3. **Замены** — таблица палитры:
   - **точно** — блок есть в 1.7.10, маппинг по таблице;
   - **замена** — предложен аналог (бетон → окрашенная глина, дрипстоун → камень...),
     вариант можно поменять через «Заменить» (поиск по блокам твоей сборки);
   - **воздух** — блок просто удаляется;
   - «модовый блок» — если блок есть в твоей сборке (по профилю), он ставится
     с meta 0, конкретный вариант выбирай руками.
   Ориентация (фасинг ступеней/брёвен/дверей, оси) пересчитывается автоматически.
4. **Экспорт** — скачай `.schematic` и положи в папку `schematics` внутри
   `.minecraft` твоего GTNH-инстанса (создаётся Schematica), затем загрузи
   в игре через меню Schematica (клавиша «Load schematic», см. настройки управления).
   После конвертации показывается смета материалов.

Замены можно сохранить как **пресет** и применять к следующим схемам одним кликом.

## Структура проекта

```
src/lib/nbt.ts                 — своя NBT-библиотека (big/little endian, gzip, все типы тегов)
src/lib/mc/litematic.ts        — парсер .litematic (мультирегионы, битупаковка BlockStates)
src/lib/mc/sponge.ts           — парсер .schem (Sponge v1/v2/v3)
src/lib/mc/legacy.ts           — чтение/запись legacy .schematic (big-endian, AddBlocks)
src/lib/mc/leveldat.ts         — извлечение FML ItemData из level.dat
src/lib/mc/legacy-map.ts       — таблица modern → 1.7.10 и скоринг соответствий
src/lib/mc/suggest.ts          — движок автозамен (цветовые семейства, суффиксы)
src/lib/mc/mapper.ts           — анализ палитры (статусы: точно/замена/воздух/...)
src/lib/mc/convert.ts          — конвертация + смета материалов
src/lib/data/legacy-blocks.json — 1682 записи modern → {id, meta} (из WorldEdit legacy.json)
prisma/schema.prisma           — модели Profile (карта ID) и Preset (замены)
scripts/fixtures/              — тестовые файлы (см. ниже)
scripts/refs/                  — исходники Forge 1.7.10 / WorldEdit, из которых собрана таблица
scripts/gen-legacy-map.mjs     — генератор таблицы из refs/legacy.json
scripts/copy-standalone.mjs    — кросс-платформенное копирование статики для прод-сборки
scripts/e2e.ts, e2e-real.ts    — end-to-end тесты (parse → analyze → convert → re-parse)
```

## Тестовые файлы

- `scripts/fixtures/test_level.dat` — синтетический level.dat, имитирующий GTNH
  (29 модов: GregTech, Chisel, Forestry..., 291 блок). Загрузи его как профиль —
  и весь флоу можно пройти без игры.
- `scripts/fixtures/test_house.litematic|schem|schematic` — одна и та же тестовая
  постройка в трёх форматах (проверка, что все парсеры дают одинаковую палитру).
- `scripts/fixtures/real/*.litematic` — 7 реальных построек (торговый зал, склад,
  фермы тростника/кактусов/булыжника, железная ферма).
- `scripts/fixtures/real/out/*.schematic` — уже сконвертированные результаты —
  можно сразу закинуть в игру и посмотреть.

## Решение проблем

- Скрипты кросс-платформенные: работают на Windows (PowerShell/cmd), Linux и macOS,
  нужен только Node.js 20+ (или Bun 1.1+).
- **«Не удалось разобрать файл» на шаге «Схема»** — открой консоль, где
  работает `npm run dev`: там теперь строки `[analyze] отказ: …` с
  точной причиной (имя файла, размер, первые байты, ошибки парсеров).
  Частые причины: файл лежит в ZIP-архиве (распакуй), это structure
  block .nbt или Bedrock .mcstructure (пересохрани в .litematic/.schem),
  файл повреждён/скачан не до конца. Пришли этот кусок лога — сразу
  скажу, что с файлом.
- **Кнопки не нажимаются / всё мёртвое** — ты, скорее всего, открыл приложение
  не по `localhost`. Next.js 16 режет кросс-origin дев-ресурсы, и страница
  остаётся без JS. Открывай строго <http://localhost:3000>. `127.0.0.1` уже
  добавлен в `allowedDevOrigins` (next.config.ts); если заходишь с другого
  устройства по LAN-IP — допиши свой IP туда же, например:
  `allowedDevOrigins: ["localhost", "127.0.0.1", "192.168.1.50"]`.
- **«Есть неразрешённые блоки»** — вернись на шаг «Замены» и проставь решения
  всем блокам со статусом «замена» (фильтр «замена» слева над таблицей).
- **Порт 3000 занят** — поменяй порт в `package.json`: `"dev": "next dev -p 3001"`.
- **Сломалась база** — удали `prisma/custom.db` и снова `npm run db:push`
  (профили пересоздадутся при загрузке level.dat).
- **Модовый блок ставится не тем вариантом** — так и задумано: в 1.7.10 варианты
  модовых блоков различаются meta, выбери нужный через «Заменить».

## Технические детали

- Выходной формат — legacy MCEdit .schematic: big-endian NBT, gzip, поля
  Blocks/AddBlocks (ID до 4095), Data, флаги ориентации пересчитываются
  из BlockState-свойств (facing/axis/half/rotation...).
- Скоринг соответствий: совпавшее свойство +2, отсутствующее +1, конфликт −4;
  блоки, которых нет в ванилле 1.7.10, в «точные» не попадают никогда.
- Профиль хранит карту `modid:blockname → числовой ID` из FML-карты ItemData
  твоего level.dat (в реальных файлах Forge 1.7.10 тег FML лежит в корне NBT,
  рядом с Data; вариант Data → FML тоже поддержан). Ключи блоков — с
  префиксом `\u0001`.
